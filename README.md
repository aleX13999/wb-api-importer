# Laravel Import Data

## Описание проекта

Это Laravel-приложение для импорта данных из внешних API в базу данных. Данные включают информацию о продажах, заказах, складах и доходах, которые загружаются для разных аккаунтов и сохраняются с учетом разграничения по аккаунтам.

---

## Функциональные возможности

- Импорт данных из API с поддержкой пагинации.
- Обработка нескольких аккаунтов и API токенов.
- Обработка ошибок, включая ограничение по количеству запросов (429 Too Many Requests) с повторными попытками.
- Команды Artisan для создания компаний, аккаунтов и т.д.
- Планировщик заданий для автоматического запуска импорта по расписанию.
- Логирование и вывод отладочной информации в логи.
- Защита данных разных аккаунтов с помощью поля `account_id` в таблицах.

---

## Технологии

- PHP 8.3+, Laravel 12
- GuzzleHTTP для работы с внешними API
- MySQL с нестандартным портом (настройка через Docker)
- Docker и Docker Compose для разработки и развертывания
- Carbon для работы с датами

---

## Быстрый старт

### Клонирование репозитория

### Запуск через Docker Compose

```shell
docker-compose up -d
```

### Настройка
- Отредактируйте `.env` файл, включая настройки базы данных (`DB_PORT` - нестандартный порт MySQL), а также параметры API и токенов.
- Выполните миграции:

```shell
docker-compose exec wb-api-php-fpm php artisan migrate
```

### Запуск импорта вручную

```shell
docker-compose exec wb-api-php-fpm php artisan import:data --accountId=1 --date=2025-10-01
```

### Запуск планировщика

```shell
docker-compose exec wb-api-php-fpm php artisan schedule:work
```


---

## Команды Artisan

- `app:create-company {name}` — создать компанию.
- `import:data {--accountId=*} {--date=}` — импортировать данные (можно указать один или несколько аккаунтов и дату).

---

## Архитектура базы данных

- Таблицы `companies`, `accounts`, `tokens`, `api_services`, `token_types` — для хранения компаний, аккаунтов и их токенов.
- В таблицах данных (`sales`, `orders`, `stocks`, `incomes`) есть поле `account_id` для разграничения данных разных аккаунтов.
- Используются связи и проверки для предотвращения затирания чужих данных.

---

## Обработка ошибок

- Реализован retry для обработки ошибок 429 (Too Many Requests) с экспоненциальным интервалом повторов.
- Логирование ошибок и отладочной информации.

---

## Логирование и отладка

- Вывод информации при выполнении команд через `$this->info()` и `$this->error()`.
- Запись логов в файлы при работе планировщика.
